## Kubernetes upgrades with externally managed CoreDNS

KatlOS 2026.10.4 fixes Kubernetes upgrades blocked by CoreDNS migration checks
when CoreDNS is managed outside kubeadm. The node agent respects the live
`ClusterConfiguration.dns.disabled` setting during upgrade plan and apply.
Externally managed CoreDNS deployments and configuration remain unchanged;
other kubeadm preflight checks still apply.

Upgrade `katlctl` and your KatlOS nodes to 2026.10.4, then retry the Kubernetes
upgrade with the same cluster configuration. This fix runs in the node agent.
Follow the [host upgrade procedure](https://github.com/katl-dev/katl/blob/main/docs/operations/upgrade-host.md)
before resuming the [Kubernetes upgrade procedure](https://github.com/katl-dev/katl/blob/main/docs/operations/upgrade-kubernetes.md).

## Known limitations

- Host reboot, shutdown, and upgrade can hang while Ceph RBD filesystems remain
  mounted. Arrange and verify storage teardown before host maintenance. See the
  [host upgrade preconditions](https://github.com/katl-dev/katl/blob/main/docs/operations/upgrade-host.md#preconditions).
- The LTS kernel retains a vendor regression in fixed-event ACPI power-button
  handling, so firmware power-button shutdown can fail. See the
  [ACPI shutdown tracking issue](https://github.com/katl-dev/katl/issues/388).
