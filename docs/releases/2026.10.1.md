## Upgrade and configure networking

KatlOS 2026.10.1 retains Fedora 44 for both kernel flavours. Fedora release
selection is centralized for future upgrades; this release does not switch
nodes to Fedora 45.

Upgrade both `katlctl` and your nodes to 2026.10.1 using the
[host upgrade procedure](https://github.com/katl-dev/katl/blob/main/docs/operations/upgrade-host.md).

Native systemd network files can now apply live. Planning and apply warn that
connectivity can be interrupted and that the runtime network might differ from
the saved configuration. Inspect the network after applying. Some changes need
interface recreation or a reboot, including `.link` settings on existing
interfaces. Use `--mode next-boot` to defer changes until a reboot. See
[configure nodes](https://github.com/katl-dev/katl/blob/main/docs/operations/configure-nodes.md)
for supported files and recovery guidance.

## Known limitations

Host reboot, shutdown, and upgrade can hang while Ceph RBD filesystems remain
mounted. Katl does not automatically quiesce storage workloads or guarantee CSI
staging cleanup before stopping their dependencies. Arrange and verify storage
teardown outside Katl before host maintenance; ordinary workload drain is not a
verified workaround. See the [host upgrade preconditions](https://github.com/katl-dev/katl/blob/main/docs/operations/upgrade-host.md#preconditions).

Install your CNI and wait for the node to become Ready before applying kubelet
configuration changes. A pre-CNI apply can persist the configuration and restart
kubelet, then fail its Node Ready health check. See [apply cluster configuration](https://github.com/katl-dev/katl/blob/main/docs/operations/configure-nodes.md).
