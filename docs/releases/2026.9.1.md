## Recover a failed kubelet configuration apply

This release fixes node-local kubelet applies that fail with `live KubeletConfiguration does not contain the desired fields` when the shared kubelet ConfigMap lacks inherited defaults, such as `systemReserved.memory`.

Upgrade both `katlctl` and your nodes to 2026.9.1 using the [host upgrade procedure](https://github.com/katl-dev/katl/blob/main/docs/operations/upgrade-host.md), then rerun your original `katlctl cluster apply` command. Reinstallation and manual generation deletion are unnecessary.

Host configuration committed before a Kubernetes failure remains active. Apply now reports that partial result and reconciles Kubernetes again on an unchanged retry, reusing the host generation. Kubelet retries also finish an interrupted restart before reporting success. Configuration mismatch errors identify the differing fields and their desired and actual values.
