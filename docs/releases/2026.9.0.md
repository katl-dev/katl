## First stable release

2026.9.0 is Katl's first stable release.

I have been running Katl in my home-lab cluster for ten days without issues.
That experience gives me enough confidence to call this release stable and
use it as the foundation for my cluster. I am committed to continuing to use
Katl and fixing issues in subsequent releases as they arise.

This is a statement of confidence in Katl for home-lab use, not a promise that
development is finished. Future releases may introduce changes, including
breaking changes, and bugs or regressions are still possible. Ten days in one
cluster is useful experience, not proof of reliability on every system.

## What Katl provides

KatlOS is an immutable, systemd-native Kubernetes node OS. It provides a
self-contained UEFI installer, declarative node configuration, kubeadm
bootstrap, and host upgrades with trial boots and rollback. The `katlctl` CLI
manages installation, configuration, and node lifecycle from your workstation.
Standard and LTS kernel flavours share the same home-lab support boundary.

Katl prepares and manages the nodes. You choose and operate the CNI, GitOps,
storage, backups, and workloads on top of Kubernetes.

## Compatibility and upgrades

The stable compatibility window begins with 2026.9.0. The management API policy
covers the current and two preceding published stable release series, where
the node has the required capability. Stable host upgrades also have a bounded
compatibility contract. These commitments do not freeze the `v1alpha1`
configuration authoring format or guarantee upgrades from every beta build.
See the [support boundary](https://github.com/katl-dev/katl/blob/v2026.9.0/docs/support.md)
for the scope and limits of these commitments.

Use the matching release's `katlctl` to validate and compile configuration.
Before upgrading an existing node, read the
[host upgrade guide](https://github.com/katl-dev/katl/blob/v2026.9.0/docs/operations/upgrade-host.md),
plan the upgrade, and retain independent backups. Host rollback does not undo
etcd, Kubernetes, or workload data changes. Earlier beta nodes may need the
version-specific steps described in that guide.

## Getting started and reporting issues

Follow [Build your first KatlOS cluster](https://github.com/katl-dev/katl/blob/v2026.9.0/docs/getting-started.md)
for installation and bootstrap. Katl targets x86-64 UEFI machines on a trusted
home-lab network. The stable designation does not add production support, an
availability guarantee, or a support or security-response SLA.

If you encounter a problem, [report an issue](https://github.com/katl-dev/katl/issues/new/choose)
with the release version, a redacted configuration, and the steps needed to
reproduce it. The [troubleshooting guide](https://github.com/katl-dev/katl/blob/v2026.9.0/docs/operations/troubleshoot.md)
explains how to collect evidence without exposing secrets.
