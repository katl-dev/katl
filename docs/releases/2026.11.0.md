## Upgrade to KatlOS 2026.11.0

KatlOS 2026.11.0 moves both kernel flavours to Fedora 45. The standard kernel
is `7.3.3-300.fc45.x86_64`, and the LTS kernel is `6.18.60-200.fc45.x86_64`.
Kernel updates are discovered and qualified independently for each flavour.

Use the 2026.11.0 `katlctl` and upgrade your KatlOS nodes before starting a
Kubernetes upgrade. Follow the [host upgrade procedure](https://github.com/katl-dev/katl/blob/v2026.11.0/docs/operations/upgrade-host.md)
for planning, flavour selection, upgrade, and rollback. Cilium users should
check the [tested Cilium configuration](https://github.com/katl-dev/katl/blob/v2026.11.0/docs/operations/cilium.md)
before upgrading the host kernel.

## Native shutdown

The LTS vendor kernel restores fixed-event ACPI power-button handling. The
installer starts logind so firmware power-button events trigger shutdown.
`katldev installer stop` requests ACPI shutdown and waits for confirmed
poweroff, with timeout recovery guidance and an explicit `--force` option.

Configure kubelet shutdown budgets to give workloads time to terminate during
host shutdown. Follow [Prepare a Kubernetes node for host maintenance](https://github.com/katl-dev/katl/blob/v2026.11.0/docs/operations/maintain-node.md).

## Control-plane configuration and Kubernetes upgrades

`katlctl cluster apply` applies native control-plane patch changes even when
the shared kubeadm `ClusterConfiguration` already matches. It regenerates the
affected static Pod manifests and waits for healthy replacement pods.
Repeating an apply preserves components whose rendered manifests match.

After upgrading nodes, rerun `katlctl cluster apply` with your configuration
if an earlier apply retained control-plane patches without updating the live
manifests. See [Apply cluster configuration](https://github.com/katl-dev/katl/blob/v2026.11.0/docs/operations/configure-nodes.md).

Stacked-etcd Kubernetes upgrades require direct voter health, quorum,
catch-up, and verified snapshot evidence. Katl prepares pending control planes
before the first mutation and stops when recovery is required. Host generation
rollback preserves the Kubernetes and etcd state produced by the rollout.
Follow the [Kubernetes upgrade procedure](https://github.com/katl-dev/katl/blob/v2026.11.0/docs/operations/upgrade-kubernetes.md).

## External Kubernetes control planes

KatlOS workers can join control planes managed outside Katl, including Talos,
through native kubelet TLS bootstrap. Configuration apply, kubelet changes,
Kubernetes upgrades, and KatlOS upgrades use the normal `katlctl` commands.
The external cluster owns certificate approval and renewal policy,
networking, and workloads. Follow [Join an external control plane](https://github.com/katl-dev/katl/blob/v2026.11.0/docs/operations/external-workers.md).
