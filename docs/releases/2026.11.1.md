## Upgrade to KatlOS 2026.11.1

KatlOS 2026.11.1 updates the standard kernel to `7.3.4-300.fc45.x86_64` and
the LTS kernel to `6.18.64-200.fc45.x86_64`.

Nodes must run KatlOS 2026.10.0 or later before upgrading to this release.
Upgrade older nodes to 2026.11.0 first. Use the 2026.11.1 `katlctl` to
validate your configuration and to upgrade, following the
[host upgrade procedure](https://github.com/katl-dev/katl/blob/v2026.11.1/docs/operations/upgrade-host.md).

## Required configuration changes

Nodes now register with Kubernetes using their ClusterConfig labels and
taints, passed through kubeadm, rather than through Node manifests applied at
bootstrap. Validation is stricter as a result, so run `katlctl config validate`
with the 2026.11.1 `katlctl` before you apply:

- Labels in the `kubernetes.io` and `k8s.io` namespaces must be ones kubelet
  may set on its own Node, such as `topology.kubernetes.io/zone`. Remove
  others, such as `node-role.kubernetes.io/worker`, from `cluster.yaml` and
  set them with `kubectl label node`.
- Native kubeadm input may no longer set `node-labels` or registration
  taints. Move them to `nodes[].kubernetes.labels` and `taints`.

For a node that has already joined, `cluster apply` records label and taint
changes and prints the `kubectl` commands that update the Node. Upgrade a
node before applying label or taint changes to it, since older node runtimes
reject them. See
[Node labels and taints](https://github.com/katl-dev/katl/blob/v2026.11.1/docs/reference/cluster-config.md#node-labels-and-taints).

## Behaviour changes

- Enabled units now start before networking at boot, so native ordering such
  as `Before=network-pre.target` holds against networkd, SSH, and the
  management agent.
- A live apply deletes the virtual network devices whose `.netdev` units were
  removed. A changed `.netdev` waits for the next boot, and `--mode live` is
  refused for it. Katl refuses to delete a device that carries a management,
  Kubernetes, or control-plane address. List devices in
  `hostConfiguration.preservedNetdevs` to keep plain networkd behaviour. See
  [Virtual network devices](https://github.com/katl-dev/katl/blob/v2026.11.1/docs/reference/cluster-config.md#virtual-network-devices).
- `katlctl` no longer scans local subnets for installers. Pass installer
  addresses explicitly or take them from `cluster.yaml`. `install apply` now
  exits with an error when no node was waiting for configuration.
- Management mutations wait until the current boot's health settles, and
  reboot, upgrade, and join wait for the health of this boot rather than
  an earlier boot of the same generation.
- The installer stages remote KatlOS images in RAM-backed `/tmp` and checks
  available memory before changing disks. Installer machines need at least
  2 GiB of RAM.

## Node and cluster management

- `katlctl cluster apply --node NAME --endpoint CURRENT` and `katlctl node
  reboot --endpoint CURRENT` move a joined worker to a new address. Follow
  [Re-address a worker](https://github.com/katl-dev/katl/blob/v2026.11.1/docs/operations/change-cluster-nodes.md#re-address-a-worker).
- `katlctl config add-node CONFIG --installer ADDRESS` adds a waiting
  installer's node to an existing `cluster.yaml`. See
  [Add one node](https://github.com/katl-dev/katl/blob/v2026.11.1/docs/operations/change-cluster-nodes.md#add-one-node).
- `katlctl cluster etcd snapshot --output PATH` saves a verified etcd
  snapshot, and Kubernetes upgrades now keep only the two newest pre-upgrade
  snapshots on each control plane. See
  [Back up etcd](https://github.com/katl-dev/katl/blob/v2026.11.1/docs/operations/back-up-etcd.md).
- Node and cluster status report kubeadm certificate expiry, and
  `kubernetes upgrade` refuses to start while a control-plane certificate has
  expired. See
  [Renew Kubernetes certificates](https://github.com/katl-dev/katl/blob/v2026.11.1/docs/operations/renew-certificates.md).
- `nftables.service` ships disabled with a scoped ruleset for operators who
  want a host firewall. Enable it through `enabledUnits` and supply
  `/etc/sysconfig/nftables.conf`. See
  [Network trust](https://github.com/katl-dev/katl/blob/v2026.11.1/docs/support.md#network-trust).
