## External Kubernetes control planes

KatlOS workers can join a Kubernetes control plane managed outside Katl,
including Talos, through native kubelet TLS bootstrap. Configuration apply,
kubelet changes, Kubernetes upgrades, and KatlOS upgrades use the normal
`katlctl` commands. The external cluster owns certificate approval and renewal
policy, networking, and workloads.

Follow [Join a worker to an external control plane](https://github.com/katl-dev/katl/blob/v2026.11.0-beta.1/docs/operations/external-workers.md)
for provisioning, bootstrap authorization, portable Talos add-ons, enrollment,
and validation.

## Kubernetes control-plane upgrades

Use this beta's `katlctl` and upgrade KatlOS nodes before starting a Kubernetes
rollout. Stacked-etcd upgrades require direct voter health, quorum, catch-up,
and verified snapshot evidence. Katl prepares every pending control plane
before the first mutation and stops when recovery is required.

Host generation rollback does not reverse etcd or Kubernetes state changes.
Follow the [Kubernetes upgrade procedure](https://github.com/katl-dev/katl/blob/v2026.11.0-beta.1/docs/operations/upgrade-kubernetes.md)
for planning, execution, and recovery.

## Known limitations

- Host reboot, shutdown, and upgrade can hang while Ceph RBD filesystems remain
  mounted. Arrange and verify storage teardown before host maintenance. See the
  [host upgrade preconditions](https://github.com/katl-dev/katl/blob/v2026.11.0-beta.1/docs/operations/upgrade-host.md#preconditions).
- The LTS kernel retains a vendor regression in fixed-event ACPI power-button
  handling, so firmware power-button shutdown can fail. See the
  [ACPI shutdown tracking issue](https://github.com/katl-dev/katl/issues/388).
